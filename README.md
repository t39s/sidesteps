# sidesteps v0.3.1-rc.5 — кандидат для пользовательской проверки

Preview v0.3.1-rc.5 содержит ссылки «Интерфейс тренера», «Интерфейс спортсмена» и заголовок «Вход в интерфейс тренера». Стабильный выпуск v0.3.0 опубликован в `main`.
Приложение: https://t39s.github.io/sidesteps/
Preview: https://t39s.github.io/sidesteps/preview/

Рабочие параметры preview — 20 интервалов, отдых 120 секунд, минимальный промежуток между касаниями 500 мс.

## Спортивные профили

В наборе ровно один базовый профиль для самостоятельных тренировок. Чтобы провести тренировку дополнительного профиля, Тренер выбирает его единственным участником занятия. После ввода PIN полномочия действуют при переходах между управлением, измерением, результатами и историей. Завершить сеанс можно ссылкой «Интерфейс спортсмена» или перезагрузкой страницы. Приложение предложит закончить активное занятие перед явным выходом.

В истории завершённой тренировки под «Подробнее» доступны комментарии спортсмена и тренера. Без PIN в своей самостоятельной истории можно изменять комментарий спортсмена и читать оба. Тренер может редактировать оба в разрешённой истории. Архивы v5 и предыдущих v6 читаются. Различия в тексте одной тренировки приводят к отказу от импорта.

## Обновление и данные

Перед проверкой сохраните JSON из стабильной версии и закройте другие вкладки sidesteps, включая установленную PWA. Preview и основной сайт используют общее хранилище origin: это проверка на данных того же браузера. После начала работы v6 не продолжайте измерения старой версией: новые записи обратно в v5 автоматически не переносятся.

Один профиль v5 мигрирует автоматически. Для нескольких нужен PIN и явный выбор базового. До выбора v6 не создаётся, исходный v5 не меняется; после перехода v5 сохраняется. Обычное восстановление прерванной попытки запускается после перехода. Если PIN недоступен, требуется восстановить конфигурацию PIN; обхода и автоматического выбора нет.

Импорт JSON v6/v5/v1–v4 строит кандидата в памяти. Совпадающий ID требует совпадения имени и всей истории; конфликт отклоняет весь импорт. Это намеренно отклоняет и дополняющие архивы одного ID. Имена не отождествляют разные ID. Повтор одинакового архива идемпотентен. При первоначальном импорте нескольких профилей Тренер выбирает базовый. Импорт не меняет существующее назначение базы и не выдаёт полномочий. Полной замены данных из резервной копии нет.

Локально: `node --check model.js`, `node --check app.js`, `node --check migration.js`, `node --check sw.js`, `node --test tests/*.test.cjs`, `sha256sum -c MANIFEST_SHA256.txt`. ## Цель и устройство

Один автономный PWA для одного постоянного физкультурного упражнения. Анализируется собственная динамика времени спортсмена; сравнение разных спортсменов не предусмотрено. Роли: администратор и спортсмен. Режимы измерения: «С отсечками» и «Старт–Стоп».

- Спортсмен использует свой смартфон или смартфон администратора. Администратор подготавливает занятие и управляет профилями на своём смартфоне. Вход по PIN открывается по ссылке «Войти» в подвале.
- Сценарий на смартфоне администратора доступен для одного участника либо для двух в автоматической очереди А1→Б1→А2→Б2. Две попытки по умолчанию; можно выбрать одну.
- При одном участнике после первой попытки начинается двухминутный отдых с кнопкой «Начать раньше»; при двух участниках отдельного отдыха нет.
- Показ результата между попытками — 5, 10 или 15 секунд (текущая экспериментальная конфигурация: 10 секунд). Итоговый экран не ограничен по времени.
- История показывает пять последних тренировок на смартфоне администратора, подробные результаты попыток, график с нулевой вертикальной осью. Рекорд определяется по успешным попыткам; первая тренировка — исходный ориентир.
- Голос сообщает время (с округлением до 0,1 с), новый рекорд, следующего участника и окончание планового отдыха. Голос можно отключить, если это разрешено общей политикой.

## Анимация запуска

В Настройках после блока «Тренировка» доступны три строки с уменьшенными работающими образцами: «Сияние» (исходный плавный цикл 1,8 с), «Пульсация» (усиленные импульсы 2 Гц, 200 мс) и «Без анимации». Нажатие всей строки выбирает вариант. Без ручного выбора весь первый календарный день на устройстве используется «Пульсация», со второго — «Сияние». Дата определяется по местному времени устройства. Правило одинаково для режимов Спортсмен и Тренер. Ручной выбор сразу получает приоритет, сохраняется при перезагрузке и применяется перед каждой попыткой. Приложение не определяет первый день отдельного спортсмена на устройстве тренера; за выбор подсказки для него отвечает тренер. Системная настройка уменьшения движения имеет приоритет.

## Управление тренировкой

- «Отменить запуск» доступна только до истечения `attemptCancelWindowSec`. Повтор — тот же спортсмен и номер попытки. Для второй попытки возвращается оставшийся отдых; «Начать раньше» доступна снова.
- Во время идущей попытки крестик запрашивает системное подтверждение. Отказ возвращает к той же попытке, время ожидания входит в её длительность. «Отменить запуск» работает без подтверждения.
- Крестик справа в шапке завершает тренировку текущего спортсмена; в открытом управлении тренера — всё занятие. Завершённые результаты сохраняются, второй спортсмен может продолжить.
- События строятся из существующих записей попыток и тренировок, без отдельного экрана журнала. Подробности: [управление тренировкой](docs/TRAINING_CONTROL.md).
- Параметры стабильного выпуска — **20 отсечек и отдых 120 секунд**.

## Запуск

1. Распакуйте каталог в директорию статического веб-сервера; открытие через `file://` не поддерживается.
2. Для локального запуска: `python -m http.server 8000` из каталога приложения; откройте `http://localhost:8000/`.
3. Для использования на телефоне разместите на **HTTPS** или доступном локальном безопасном origin. PWA требует первоначальной загрузки онлайн.
4. Перед переходом с 1.4.3 **сохраните JSON-экспорт** из 1.4.3.
5. Реальная работа HTTPS/офлайн на целевом телефоне не подтверждена автоматическими тестами.

## PIN — доступ администратора

**В выпуске проверочные данные PIN администратора настроены:** в `config.json` записаны случайная соль и PBKDF2-SHA256 verifier, без PIN открытым текстом. PIN предоставлен заказчиком и используется для открытия режима администратора. Это защита от случайного доступа спортсменов, не защита от целенаправленного перебора короткого PIN. **Не передавайте PIN другим пользователям.**

Для замены PIN разработчик использует служебный скрипт `tools/configure-pin.mjs` (читает PIN через stdin, не печатает значение) и публикует новый `config.json` с солью и PBKDF2-SHA256 verifier. В репозитории не должно быть PIN открытым текстом. Клиентский PIN защищает только от случайных действий, не от намеренного обхода. **Не публикуйте тестовый PIN из браузерных автотестов как производственный.**

## Настройки `config.json`

Ниже **пример структуры**, не используйте его вместо реального `config.json` из выпуска.

```json
{
  "minTapGapMs": 500,
  "intervalCount": 20,
  "restDurationSec": 120,
  "attemptCancelWindowSec": 10,
  "resultDisplaySec": 5,
  "recordDisplaySec": 10,
  "audioPolicy": "user-controllable",
  "trainerAccess": {"algorithm": "PBKDF2-SHA256", "iterations": 200000, "saltB64": "<сгенерированная соль>", "verifierB64": "<сгенерированный проверочный хеш>"}
}
```

- `minTapGapMs`: 0–60000 мс; повторный ввод принимается **строго позже** этой границы.
- `intervalCount`: 1–200 интервалов; 20 интервалов = 21 принятое касание.
- `restDurationSec`: отдых в секундах, диапазон 0–600; в стабильном выпуске — 120 секунд.
- `attemptCancelWindowSec`: окно отмены ошибочного запуска, целое 1–60 секунд; сейчас 10. На самой границе отмена уже недоступна.
- `resultDisplaySec`: время восприятия обычного результата с момента его появления, в обоих режимах; сейчас 5 секунд.
- `recordDisplaySec`: время восприятия результата с личным рекордом с момента его появления, в обоих режимах; сейчас 10 секунд. Оба параметра допускают 5, 10 или 15 секунд. Озвучка идёт параллельно, её длительность не меняет время показа.
- `audioPolicy`: `off` (звук выключен, переключатель скрыт) или `user-controllable` (состояние на устройстве).
- `trainerAccess`: настроенная соль и проверочный хеш PIN; сам PIN в файле отсутствует.

История, профили и активный сеанс сохраняются локально. При загрузке страницы звук выключается, настройки будущей личной тренировки возвращаются к двум попыткам и режиму «С отсечками». Выбор пользователя действует до следующей загрузки страницы. План и режим уже начатой тренировки восстанавливаются. Действующий контракт и основания изменения — [B-008](docs/B-008_STARTUP_DEFAULTS.md). Приложение не использует облачную синхронизацию и не предоставляет администратору удалённый доступ к чужим смартфонам.

## Данные, восстановление, миграция

- Новая схема: `schemaVersion=5`, ключ `interval-lab:data:v5`.
- При первом запуске читается прежний `interval-lab:data:v1` (форматы v1–v4), данные преобразуются в новый ключ. **Старый ключ не перезаписывается.**
- Незавершённые серии v4 становятся `legacy_pending`: новые сроки 5/10 минут **не применяются автоматически** к историческим сериям. Их можно продолжить из личного интерфейса.
- Работавшее измерение после закрытия браузера становится прерванным, а зачётная попытка повторяется. Завершённые результаты сохраняются.
- Одиночная тренировка с ожидающей второй попыткой закрывается по более раннему сроку: +5 минут от завершения А1 либо +10 минут от начала А1. Запущенная до срока вторая попытка не обрывается.
- Рекорд вычисляется из сохранённых попыток и исторического архива; график — из завершённых тренировок. После удаления администратором расчёты обновляются.
- JSON-экспорт и импорт истории. Спортсмен на своём смартфоне экспортирует свою историю, администратор — локальную историю всех.
- Удаление завершённых результатов — только администратору; удаление прерванной попытки разрешено спортсмену. Измеренные значения не редактируются.

## Проверка

- `node --test tests/*.test.cjs` — автоматические проверки модели, интерфейса, восстановления, отмены запуска и миграционных инвариантов.
- `python tests/browser_smoke.py` — 11 UI-сценариев с Chromium через `about:blank` и подменёнными `fetch`/`localStorage`, поскольку браузер окружения блокирует сетевую навигацию политикой. В тестах используется **только тестовый PIN**, и WebCrypto для сценария входа **имитируется**. Эти тесты **не доказывают** работоспособность настоящих PWA-установки, сервис-воркера, хранения данных браузера, Web Speech или WebCrypto на телефоне.
- PIN-verifier проверен отдельно через Node.js `crypto.webcrypto.subtle`: верный PIN совпадает, заведомо неверный отвергается; тест не раскрывает PIN и не эквивалентен браузерному E2E.
- SHA-256: см. `MANIFEST_SHA256.txt`.

## Ограничения и риски выпуска

1. **PIN получен и сконфигурирован.** Проверка WebCrypto и пользовательского ввода в действительном браузере на HTTPS-устройстве остаётся обязательной до финального выпуска.
2. Реальные телефоны и браузеры администратора и спортсменов не проверялись. Нужны наблюдения по 5/10/15 секундам, доступности голоса, корректности офлайн-режима, Wake Lock и UX второго класса.
3. В этой версии основные измерительные сценарии перенесены в новую реализацию. Это не побайтовая модификация 1.4.3; функциональная регрессия возможна в неохваченных тестами ветвях. Существующее приложение не заменять без регрессионного прогона.
4. Функция ручного «Завершить досрочно» **не перенесена как активная команда** — решение заказчика о её пересмотре отложено. Исторические неполные записи сохраняются при импорте.
5. `localStorage` не защищает от очистки данных браузера. Создавайте резервные JSON-копии перед обновлениями и удалениями.
6. При одновременной работе в двух вкладках показано уведомление о конфликте, но отсутствует транзакционная защита от гонок между вкладками. Работайте в одной вкладке.
7. PIN-ограничение — UX-защита от случайных действий спортсмена, а не информационно-безопасная авторизация.

**Исторический источник:** [`t39s/dev-sandbox/interval-lab`](https://github.com/t39s/dev-sandbox/tree/main/interval-lab), baseline 1.4.3. **Текущая стабильная baseline:** sidesteps v0.2.6 в ветке `main`. Известные проблемы: [`KNOWN_ISSUES.md`](KNOWN_ISSUES.md).

## Проверки и публикация

Автоматический короткий прогон применяется к изменениям только версии и перечисленных файлов сведений о выпуске. Остальные изменения запускают полную регрессию. Сравнение выполняется с последним успешно проверенным предком, включая изменения из пропущенных CI-коммитов.

Для рассмотренных разработчиком изменений надписей и вёрстки можно вручную запустить Validate sidesteps candidate в ветке develop с scope=ui. Этот выбор допускает файлы интерфейса и тестов. Изменения model.js, migration.js, config.json, workflow, служебных скриптов и неизвестных файлов принудительно включают полную регрессию. scope=full всегда выполняет полный прогон.

Короткая проверка включает синтаксис, JSON, контрольные суммы, все Node-тесты и браузерные переходы входа/выхода на ширине 375 и 430 px. Она проверяет ограниченные сценарии и требует осознанного выбора для изменений надписей. Полный прогон дополняет её всеми существующими браузерными тестами.

Публикация Preview скачивает архив из успешного запуска для точного commit, сверяет идентификатор и SHA-256 и публикует извлечённое содержимое. Повторные Node-тесты при такой публикации исключены. Для push в main и ручной публикации сохраняются проверки исходников. Python-пакеты и Chromium кэшируются. Фактические результаты и длительности доступны в GitHub Actions.
