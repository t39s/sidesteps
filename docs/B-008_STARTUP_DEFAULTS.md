# B-008 — значения по умолчанию при загрузке страницы

17 ноября 2026 года. Кандидат `sidesteps v0.2.8-rc.2`.

## Основания и исходное состояние

Стабильная baseline — `v0.2.7`, `main`, коммит `1c64507235529a2434f35d4251e5de4381416306`.
Исходная ветка разработки — `develop`, `v0.2.8-rc.1`, коммит `998a49a2d6528ea697aa826bde069eb144ffc38a`.
Обе ветки сверены с GitHub перед изменением. Контрольные суммы и 29 исходных тестов прошли.

Применён действующий процесс этого продуктового чата: точечные изменения от актуальной `develop`, проверки Node и SHA-256, публикация кандидата на preview. Стабильная публикация проходит отдельную приёмку и PR в `main`. Проверены README, продуктовая спецификация, технический проект, известные ограничения и оба workflow. Дополнительных AGENTS.md и файлов правил в дереве репозитория не обнаружено. Правила других продуктов к sidesteps не переносились.

## Проверка предположения о регрессии

В исходном кандидате настройки `device.soloPlannedAttempts`, `device.soloMeasurementMode` и `device.soundEnabled` читались из localStorage без сброса при загрузке. Сохранённые одна попытка, «Старт–Стоп» и включённый звук воспроизводились после повторной инициализации страницы.

В `v0.2.6` число попыток в личной форме изначально было равно двум, а переменная `exerciseMode` инициализировалась значением `intervals`. Автоматический возврат этих двух полей после загрузки подтверждён кодом. Он обеспечивался начальным состоянием интерфейса, отдельной общей операции сброса всех параметров не было. Вход во вкладку нового упражнения также возвращал интервальный режим.

[Коммит `dbc0757`](https://github.com/t39s/sidesteps/commit/dbc075707762f0656d8f737364283928e6914978), вошедший в `v0.2.7`, перенёс настройки в шестерёнку и сделал их сохраняемыми. Это установившееся в том обсуждении поведение изменяется новой задачей B-008 в части перезагрузки. Сброс при начале новой тренировки B-008 исключает.

Для звука регрессия прежнего общего сброса не подтверждена. Продуктовый draft, §5.1, предписывал сохранять звук при перезапуске, а технический draft, §6.2, предлагал включённый звук при первом запуске. Прямое требование владельца в B-008 устанавливает новое действующее правило — при загрузке звук выключен. Оно имеет приоритет над прежними текстами и кодом.

## Действующий контракт B-008

| Параметр | После загрузки страницы | Основание |
|---|---|---|
| Звук | Выключен | Прямое требование B-008 |
| План будущей личной тренировки | Две попытки | Спецификация, §1.2 и UC-01; прежняя личная форма |
| Режим будущей личной тренировки | С отсечками | Личная форма `v0.2.6`; принятые в этом чате значения по умолчанию |
| Число отсечек | Из загруженного config.json | Продуктовый §5.1; 4 на preview и 20 в стабильной baseline |
| Отдых и пауза результата | Из config.json | Действующая конфигурация сборки; в кандидате 120 и 5 секунд |

Изменения пользователя применяются ко следующим тренировкам в текущей странице. Начало новой тренировки само по себе значения не сбрасывает.

При восстановлении уже начатой тренировки её `plannedAttempts`, режим измерения, первая завершённая попытка и очередь участников сохраняются. Это следует из действующего требования восстановления сеанса. Настройки будущей тренировки сбрасываются отдельно от плана активной. Работавший при перезагрузке секундомер по существующим правилам отмечается прерванным.

Профили, история, исходный ключ миграции и границы PIN-доступа сохраняются. При ошибке чтения истории операция установки значений по умолчанию не записывает данные поверх повреждённого содержимого.

## Выполненные изменения

В `model.js` начальное состояние теперь содержит выключенный звук, две попытки и интервальный режим. В `app.js` значения устанавливаются при инициализации после восстановления модели, перед одной итоговой записью startup-состояния. Рабочий режим активной тренировки сохраняется. Обработчики запуска новой тренировки сброс не выполняют.

Действующее правило добавлено в README и отмечено рядом с историческими положениями о звуке в двух проектных документах. Контракт данных остаётся schemaVersion 5. Возврат к предыдущей сборке читает ту же схему; временные пользовательские настройки, намеренно сброшенные по B-008, автоматически восстановлены не будут.

## Проверки и границы доказательств

`tests/startup_defaults.test.cjs` проверяет первый запуск, повторную загрузку с изменёнными настройками, сохранность истории и идентичности, повторную тренировку в той же странице, восстановление между попытками, сеанс участника, PIN при повторном входе администратора и отсутствие перезаписи повреждённой истории. До исправления пять исходных сценариев этой проверки выявили расхождение, после исправления проходят все шесть.

Обновлены существующие проверки озвучки, явно включающие звук для сценария, и браузерный сценарий, который ранее требовал сохранения предпочтений после загрузки. Полный набор Node — 35 тестов. Браузерная проверка через `about:blank` или VM не доказывает Safari, офлайн-PWA и реальную Web Speech на телефоне. Новая сборка требует пользовательской проверки на iPhone перед стабильным выпуском.

## Применение FPF Library

Использована редакция `20261116T211940Z-131a343e49740e98`, исходный коммит `ailev/FPF e230eef4f6955116bf697ca9ba5e79247af1843e`. Прочитаны USING-FPF.md и первоисточники следующих паттернов.

- [SYSE.13:4.1–4.4](https://fpf.tools/SYSE.13) — установлены версии стабильной сборки, кандидата, конфигураций и исторических документов, отдельно от предположения владельца о прежнем поведении.
- [SYSE.4:4.1–4.5](https://fpf.tools/SYSE.4) — гипотеза регрессии проверена для каждого параметра. Память о прежнем поведении не использовалась как доказательство. Для выбора исправления сопоставлены код, историческое изменение и текущее требование.
- [SYSE.34:4.1–4.5](https://fpf.tools/SYSE.34) — определена граница изменения постоянных данных: предпочтения сбрасываются, история и активный сеанс восстанавливаются. Проверены существующие записи и ошибка чтения до записи новых значений.

## Статус и трудозатраты

Исправление подготовлено для проверки в `v0.2.8-rc.2`. Приёмка владельцем и стабильный выпуск оформляются отдельно. Фактическое время работы человека не измерялось; время автономного исполнения AI не выдаётся за трудозатраты человека.

Предшествующее уточнение об отсутствии отметки «лучшая из двух» при одной попытке остаётся отдельным изменением и не включено в B-008.
